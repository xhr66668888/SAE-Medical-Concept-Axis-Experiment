Decision procedure (press ?)

Judge the state as of the final turn. Apply in order, stop at the first that fires.

  1. A user request with no answer in any later assistant turn → unanswered question
  2. Two task-critical facts conflict, unreconciled → contradiction
  3. A referent needed to act is under-determined (≥2 live candidates) → ambiguous reference
  4. Otherwise all requests answered, no conflict, referents fixed → resolved
  5. Any of 1–3 genuinely arguable both ways → indeterminate

Never sufficient on its own: a single repetition, disfluency, brevity, politeness, hedging. Repetition is not evidence in either direction — a read-back the assistant asked for is resolved; a quiet contradiction with no repetition is unresolved.

Resolved subtypes: read-back (user repeats because asked), emphasis repeat (restates an already-accepted preference), clean progress (information complete, task proceeds).

Some items are excerpts of real, unscripted conversation and start mid-stream. Where the call depends on a turn that is not shown, that is what indeterminate is for. A dropped thread neither speaker treated as owed is resolved, not unresolved.
